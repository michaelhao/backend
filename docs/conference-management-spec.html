時間順序規則

四個時間欄位的順序約束貫穿新增與修改的驗證；先看懂規則，再讀下方逐項規格。

四時間欄位順序：報名開始 < 報名截止 ≤ 活動開始 < 活動結束

register_started_at報名開始
register_ended_at報名截止
started_at活動開始
（可等於報名截止）
ended_at活動結束
時間欄位不與 now() 比較——允許管理員補建歷史說明會。順序由 ConferenceRequest 以 after / before_or_equal 規則驗證。

資料與列表

R1Conference 資料模型

系統 SHALL 維護 conferences 資料表：id（int unsigned 主鍵）、name（字串，最長 100）、status（Active=1 或 Inactive=0）、started_at、ended_at、register_started_at、register_ended_at（皆 datetime）、created_at、updated_at。資料表 SHALL 對 status 與 started_at 建立索引。
執行 migration 建立資料表無直接測試 — migration 結構
WHEN執行 php artisan migrate
THEN資料庫出現 conferences 資料表，欄位與型別與上述規格相符
ANDstatus 與 started_at 索引已建立
Model 正確 cast status 為 enum無直接測試 — 由 factory／CRUD 間接覆蓋
WHEN讀取一筆 Conference 記錄
THEN$conference->status 為 App\Enums\ConferenceStatus 的實例

R2列表檢視

系統 SHALL 提供 GET /conferences 列表頁，顯示所有說明會（含 Active 與 Inactive），支援依 keyword 搜尋 name、依 status 篩選與 per_page 分頁。頁面 SHALL 受 Conference.index 權限保護。per_page SHALL 限定白名單 {50, 100, 150, 200}；不在白名單或未提供時 SHALL fallback 為 50。
per_page 白名單與 filters 萃取由 Controller 處理後傳入 Service（getIndexData(array $filters, int $perPage)），Service 不接觸 Request。
授權使用者瀏覽列表ConferenceCrudTest::test_admin_can_access_conference_index
WHEN擁有 Conference.index 權限的使用者 GET /conferences
THEN回傳 HTTP 200 與包含分頁結果的 admin.conferences.index view
未授權使用者被擋無直接測試 — Viewer 角色亦具 index 權限
WHEN不具 Conference.index 權限的使用者 GET /conferences
THEN系統拒絕存取（依專案權限 middleware 回應 403 或導向）
依關鍵字過濾ConferenceCrudTest::test_index_filters_by_keyword
WHEN使用者 GET /conferences?keyword=春季
THEN回傳結果僅包含 name 含「春季」的說明會
依狀態過濾ConferenceCrudTest::test_index_filters_by_status
WHEN使用者 GET /conferences?status=0
THEN回傳結果僅包含 status = Inactive 的說明會
per_page 白名單外的值 fallback 為 50ConferenceCrudTest::test_per_page_outside_whitelist_falls_back_to_50
WHEN使用者 GET /conferences?per_page=9999
THEN回傳分頁大小為 50，不以使用者輸入為準

新增與修改

R3新增說明會

系統 SHALL 提供 GET /conferences/create 顯示表單、POST /conferences 接收並建立。兩者 SHALL 受 Conference.create 權限保護。所有欄位 SHALL 通過驗證後才寫入。建立成功後 SHALL 導向 /conferences 並帶 success flash。
成功建立ConferenceCrudTest::test_admin_can_create_conference
WHEN授權使用者 POST 合法表單（name、status、四個時間欄位皆合法且順序正確）
THEN資料庫新增一筆 conferences 記錄
AND回應為 302 導向 conferences.index
ANDsession 含成功訊息
必填欄位缺漏時不寫入ConferenceCrudTest::test_store_fails_when_name_missing
WHEN授權使用者 POST 缺少 name 或 status 或任一時間欄位的表單
THEN回應為 422（或 redirect back with errors）
AND資料庫未新增任何 conferences 記錄
時間順序錯誤時不寫入ConferenceCrudTest::test_store_fails_when_register_ended_after_started
WHEN授權使用者 POST 時間欄位不滿足順序規則的表單
THEN回應為 422（或 redirect back with errors）
AND資料庫未新增任何 conferences 記錄

R4修改說明會

系統 SHALL 提供 GET /conferences/{id}/edit 顯示編輯表單、PUT /conferences/{id} 接收更新。兩者 SHALL 受 Conference.update 權限保護。更新成功後 SHALL 導向 /conferences 並帶 success flash。找不到指定 id 時 SHALL 導回 /conferences 並帶 error flash。
查無記錄的判斷由 Controller 委派 ConferenceService::findConferenceById()（再經 ConferenceRepository::getById()），Controller 不直接接觸 Eloquent。
成功更新ConferenceCrudTest::test_admin_can_update_conference
WHEN授權使用者 PUT 合法表單至 /conferences/{existing_id}
THEN該筆記錄欄位被更新
AND回應為 302 導向 conferences.index 並帶 success flash
找不到 idConferenceCrudTest::test_edit_for_non_existing_id_redirects_with_error
WHEN授權使用者 GET /conferences/{non_existing_id}/edit
THEN回應為 302 導向 conferences.index 並帶 error flash
驗證失敗不變更資料ConferenceCrudTest::test_update_validation_failure_keeps_record_unchanged
WHEN授權使用者 PUT 時間順序錯誤的表單
THEN資料庫該筆記錄保持原狀
AND回應為 422 或 redirect back with errors

R5時間欄位順序驗證

系統 SHALL 在寫入（建立或修改）時驗證四個時間欄位滿足順序：register_started_at < register_ended_at ≤ started_at < ended_at。任一條件不滿足 SHALL 視為驗證錯誤。
報名截止晚於活動開始ConferenceCrudTest::test_store_fails_when_register_ended_after_started
WHEN使用者提交 register_ended_at > started_at
THEN系統回傳驗證錯誤，不進行寫入
活動結束不晚於活動開始ConferenceCrudTest::test_store_fails_when_ended_not_after_started
WHEN使用者提交 ended_at ≤ started_at
THEN系統回傳驗證錯誤，不進行寫入
報名開始晚於報名截止ConferenceCrudTest::test_store_fails_when_register_started_not_before_register_ended
WHEN使用者提交 register_started_at ≥ register_ended_at
THEN系統回傳驗證錯誤，不進行寫入
報名截止等於活動開始（邊界）ConferenceCrudTest::test_store_accepts_register_ended_equal_to_started
WHEN使用者提交 register_ended_at = started_at（其餘順序皆合法）
THEN系統接受，寫入成功

刻意設計（不是缺漏）

以下為依產品決策刻意排除的功能，避免後人誤判為待補項目。

R6不提供刪除功能（刻意設計）

為保留歷史紀錄，系統 MUST NOT 提供任何刪除說明會的路徑：無 DELETE 路由、無 destroy controller action、無 Conference.delete 權限、無軟刪欄位。下架 SHALL 透過 status = Inactive 達成。
DELETE 路由不存在ConferenceCrudTest::test_delete_route_is_not_registered
WHEN任何使用者 DELETE /conferences/{id}
THEN系統回應 405（Method Not Allowed）或 404
權限列表不含 Conference.deleteConferenceCrudTest::test_conference_delete_permission_is_not_registered
WHEN查詢系統已註冊之權限清單
THEN清單中不存在 Conference.delete

—刻意不做的事（彙整）

刪除 / 軟刪保留歷史紀錄；無 DELETE 路由、無 destroy、無 Conference.delete、無軟刪欄位，下架改用 status = Inactive（R6）
name 唯一性約束name 刻意允許重複——反覆舉辦同主題活動為合法情境
時間與 now() 比較四時間欄位僅檢查彼此順序，不與當下比較，允許補建歷史說明會
Deleted 狀態值ConferenceStatus 僅 Active / Inactive，無預留 Deleted
