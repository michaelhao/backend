原生 JS → Vue 島嶼 遷移實作計畫

本頁為實作計畫的閱讀版,逐階段說明「做什麼、改哪些檔、改哪些功能」。逐步程式碼與 TDD checkbox 以 Markdown 計畫為準。
目標：把 resources/js 下 18 支、約 2,077 行的原生 JS(對 Blade 已渲染 DOM 做命令式漸進增強)改寫為「Blade + Vue 3 島嶼」——每個 @vite entry 改用 mountIsland() 把一個 .vue 元件掛到 Blade 渲染的掛載點,以響應式狀態取代命令式 DOM。

目標與架構

島嶼模型如何運作、為什麼契合本專案。

架構每頁一島,Blade 出資料、Vue 接管互動

現況:每個 Blade 頁 @vite('resources/js/<feature>/<entry>.js') 載入專屬 JS,以 getElementById + data-* 讀資料、querySelector 綁事件、classList 切換顯示。這「每頁一 entry」結構天然對應 Vue 島嶼。

改寫後的資料流
{{-- Blade:渲染掛載點 + 注入伺服器資料 --}}
<div id="grade-weight-field" data-props="@json([...])"></div>
@vite('resources/js/grades/form.js')
// entry:不再操作 DOM,改掛載 Vue 元件
import mountIsland from '@/lib/mountIsland'
import GradeWeightField from './GradeWeightField.vue'
mountIsland('grade-weight-field', GradeWeightField)
三類命令式寫法 → Vue 對應(全程一致)
原生 JS 寫法Vue 島嶼作法
el.dataset.x / getElementById 讀資料→Blade @json → props
classList.toggle('hidden')→v-if / v-show 綁狀態
querySelectorAll(...).addEventListener→@click / v-model / v-for
innerHTML = '...' 拼字串→template + 響應式資料
window.axios / 裸 fetch→import http from '@/lib/http'(可被測試 mock)

全域約束

每個任務都要遵守。

規則不可踩的邊界

  • 指令一律在 Docker 容器內docker compose exec backend-api npm run …(或 docker exec wsl-backend …),不在 host 直接跑。
  • 依賴變更需使用者核准新增 vue、@vitejs/plugin-vue、vitest、@vue/test-utils、jsdom;M0 安裝前先確認同意。
  • 不動後端Laravel 路由 / Controller / Service / Repository / Model / 驗證 / 權限 / CSRF / migration 一律不改。只動 resources/js、resources/views 掛載點、vite.config.js、package.json、新增 vitest.config.js。
  • Tailwind v4 設計系統不分叉沿用 @theme token 與既有元件類(.form-control、.modal-overlay、.btn-primary、.flash-*、.chat-*);Vue SFC 用 utility,避免 <style scoped>。
  • JS 契約 class 規則在島內調整CLAUDE.md 要求 hidden、.delete-btn、#delete-modal*、.flash-message 以字面 class 留給 JS;島內改由 Vue 狀態驅動(v-if/v-show)後不再需要,島外未遷移頁仍維持原規則。
  • 每島完成後npm run test(該島 Vitest)綠燈 + npm run build 成功;commit 由人工同意,訊息結尾加 Co-Authored-By。

遷移順序與風險

由易到難、逐島可獨立上線與回退。

五階段路線

M0 基建build + 測試 + 共用件
M1 試點低風險立慣例
M2 中小型共用 modal/flash
M3 大型表單bills
M4 聊天頁即時,最高風險

原則並存、不設「切換日」

每批可獨立上線、獨立回退(git revert 該島 commit);舊原生 JS 與新 Vue 島在不同頁面長期並存。高風險集中在 M3 bills/create(637 行精靈)與 M4 chats(534 行即時),排在最後、團隊熟悉後再動,並以雙人真實環境回歸。

驗證方式

每島都要過的關卡。

關卡自動 + 人工雙軌

  • 單元測試(Vitest)docker compose exec backend-api npm run test -- <該島 .test.js>;每島 happy / 失敗 / 邊界。
  • 建置docker compose exec backend-api npm run build 成功、無未解析 import;改 token 後驗證全站樣式。
  • 人工回歸每島開對應頁實測;M3 走完整建立帳單對賬金額/payload;M4 雙人測即時行為。
  • 收尾全量全測試綠 + 全量 build + grep 掃描確認無大段命令式 UI 殘留。
