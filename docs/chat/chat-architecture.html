聊天即時架構說明

現代化即時通訊(IM)聊天功能:訊息生命週期、技術機制與關鍵實作
技術主軸:WebSocket(全雙工) + Node.js + Redis(Pub/Sub・Presence・快取) + PostgreSQL(歷史)。本文為架構說明文件,程式碼為示意範例。

架構總覽

一則訊息從「使用者按下送出」到「對方螢幕渲染出來」會經過四階段;先看全貌,再逐段深入。

1. 客戶端發送端

  • 樂觀更新(Optimistic Update):送出時先在本地產生 client_msg_id(UUID),立即以 status: 'sending' 渲染,不等伺服器回應 → UI 無延遲感。
  • 資料封裝:{ type, client_msg_id, room_id, body, sent_at }。client_msg_id 是後續冪等與去重的關鍵。
  • 觸發傳輸:連線為 OPEN 直接送;斷線中則塞入離線佇列(outbox),重連後補送。

2. 傳輸與路由層

  • 訊息以 WebSocket frame 經持久連線抵達伺服器。
  • 身分不可偽造:伺服器不信任 frame 內的 sender_id,一律使用連線鑑權後綁定在該 socket 上的 userId。
  • 房間路由:檢查該 socket 是否為 room_id 成員(權限),再決定扇出對象。

3. 持久化與廣播

  • 先持久化、後廣播:先寫 DB 取得 server_id / seq 再廣播;即使對方當下離線,訊息已落地,上線可補拉。
  • 冪等:DB 對 (room_id, client_msg_id) 設唯一鍵;重送同一 id 不產生重複列。
  • 跨節點扇出:多台 WS server 時,A 連 server-1、B 連 server-2 → server-1 寫完 DB 後 PUBLISH 到 Redis room:{id},所有節點 SUBSCRIBE 後各自推給手上的連線。

4. 客戶端接收端

  • 去重:以 server_id 比對已渲染集合,避免「自己送的」既被樂觀渲染又被廣播回來而重複。
  • XSS 安全渲染:一律 textContent / 跳脫,絕不把 body 直接塞 innerHTML。
  • 未讀計數:非當前房間 → 該房未讀 +1、總 badge 更新;當前房間且可見 → 直接標記已讀。
  • 自動捲動:只有原本貼底時才捲到底;使用者正在翻歷史時不可強拉,改顯示「↓ 新訊息」浮標。

二、技術選型與運作機制

協定選型:為何是 WebSocket

協定方向連線即時性IM 適用
HTTP 短輪詢請求/回應每次新建差低 大量空請求
長輪詢半雙工模擬掛住到有資料中過渡
SSE僅伺服器→客戶端持久 HTTP 串流高(下行)通知佳 上行需另開
WebSocket全雙工一條持久 TCP最高首選

理由:聊天是雙向高頻(雙方都會發訊、打字中、已讀回條)。WebSocket 在單一 TCP 連線上雙向傳輸,免去 HTTP 每次請求的標頭開銷,延遲最低。

交握(Handshake)與心跳(Heartbeat)

交握底層:借用 HTTP 升級,之後脫離 HTTP 走自有 frame 協定。

  • 客戶端送帶 Upgrade: websocket 的 GET,附隨機 Sec-WebSocket-Key。
  • 伺服器把 key 串上固定魔術字串 258EAFA5-E914-47DA-95CA-C5AB0DC85B11,做 SHA-1 後 base64 放進 Sec-WebSocket-Accept,回 101 Switching Protocols。此計算非為安全,而是證明對方理解 WS 協定、防快取代理誤判。
  • 之後以 frame 通訊:opcode 0x1 文字、0x2 二進位、0x8 關閉、0x9 ping、0xA pong。客戶端→伺服器的 frame 必須 masking,防代理快取污染攻擊。

心跳為何必要:TCP 可能變「半開(half-open)」—— 一端已死但另一端不知,連線看似存在卻送不到;且 NAT / 代理 / LB 會對閒置連線設逾時而悄悄掐斷。

  • 伺服器每 N 秒對每條連線送 ping(0x9),客戶端協定層自動回 pong(0xA)。
  • 伺服器為每條連線維護 isAlive:送 ping 前若上輪仍為 false → 判定死連線,terminate() 釋放資源。
  • 心跳同時保活:定期流量讓 NAT/代理不把連線當閒置切斷。

前端狀態管理與渲染優化

  • 虛擬列表(Virtual List):歷史可能上萬則 → 只渲染可視範圍 DOM(加緩衝),捲動時回收重用,避免記憶體爆量與捲動卡頓。
  • 樂觀更新:送出即渲染 sending,收 ACK 後以 client_msg_id 對位更新為 sent,失敗標 failed 可重送。
  • 防抖 / 節流:「輸入中」用 throttle(例如每 2 秒一次);捲動載入歷史、resize 用 debounce。
  • 批次渲染:極高頻時收集多則後以一次 requestAnimationFrame / DocumentFragment 批次插入,減少 reflow。
  • 去重與順序:用 seq(伺服器單調遞增序號)排序與補洞,避免亂序或重複。

資料儲存策略:Redis 與持久 DB 的分工

用途元件機制
跨節點扇出Redis Pub/Sub(或 Streams/Kafka)PUBLISH/SUBSCRIBE room:{id},解決「雙方連在不同機器」
線上狀態 PresenceRedis(SET + TTL)online:{userId} 帶 TTL,心跳續期
未讀計數Redis(原子 INCR)高頻讀寫,原子操作避免競態
近期訊息快取Redis(List)開房間秒載最近 N 則,不打 DB
歷史(真相來源)PostgreSQL / MongoDB永久保存、可查詢分頁;寫入是「訊息已送達系統」的權威依據

心法:Redis 管「快、即時、可丟失」(presence、計數、扇出、快取);持久 DB 管「慢、永久、要正確」(歷史)。寫入路徑為「先寫 DB(權威)→ 再經 Redis 扇出」,確保推播失敗也不遺失,離線者上線可補拉。

三、關鍵核心實作

3-1. 前端客戶端(JavaScript)

重點:指數退避重連(Exponential Backoff + Jitter)、樂觀更新、離線佇列、XSS 安全渲染、心跳偵測。

/**
 * ChatClient — 封裝 WebSocket 連線、收送訊息、斷線重連。
 * 安全重點:渲染一律走 escapeHtml;身分由連線時的 token 決定,不在訊息內帶 sender_id。
 */
class ChatClient {
  constructor({ url, token, onMessage, onStatus }) {
    this.url = url;                 // wss://example.com/ws
    this.token = token;            // 鑑權用(JWT),放在連線 query 或子協定
    this.onMessage = onMessage;
    this.onStatus = onStatus;      // 連線狀態回呼(connecting/open/closed)
    this.ws = null;
    this.outbox = [];              // 離線時暫存待送訊息
    this.seen = new Set();         // 已渲染的訊息 id,用於去重
    this.retries = 0;              // 重連次數(指數退避用)
    this.maxRetries = 10;
    this.manualClose = false;      // 主動關閉時不重連
    this.missedPongTimer = null;   // 偵測伺服器是否還活著
  }

  connect() {
    this.manualClose = false;
    this.onStatus?.('connecting');
    // token 放 query 僅為範例;正式環境建議用 Sec-WebSocket-Protocol 或先換短期票券,避免 token 進 log/referrer
    this.ws = new WebSocket(`${this.url}?token=${encodeURIComponent(this.token)}`);

    this.ws.onopen = () => {
      this.retries = 0;                 // 連上即重置退避
      this.onStatus?.('open');
      this._flushOutbox();              // 補送離線期間累積的訊息
      this._armPongWatchdog();          // 啟動「伺服器是否還活著」看門狗
    };

    this.ws.onmessage = (evt) => {
      let data;
      try { data = JSON.parse(evt.data); } catch { return; } // 壞封包直接丟棄

      if (data.type === 'ping') {       // 應用層心跳(若伺服器走應用層 ping)
        this._send({ type: 'pong' });
        this._armPongWatchdog();
        return;
      }
      if (data.type === 'ack') {        // 伺服器確認:把樂觀訊息標記為已送達
        this.onMessage?.({ kind: 'ack', clientMsgId: data.client_msg_id, serverId: data.server_id, seq: data.seq });
        return;
      }
      if (data.type === 'message') {
        if (this.seen.has(data.server_id)) return; // 去重(自己送的會被廣播回來)
        this.seen.add(data.server_id);
        this._armPongWatchdog();        // 收到任何資料都代表連線健康
        this.onMessage?.({ kind: 'message', msg: data });
      }
    };

    this.ws.onclose = () => {
      this.onStatus?.('closed');
      clearTimeout(this.missedPongTimer);
      if (!this.manualClose) this._scheduleReconnect();
    };

    // onerror 後瀏覽器一定會接著觸發 onclose,重連邏輯統一放 onclose
    this.ws.onerror = () => this.ws?.close();
  }

  /** 發送訊息:樂觀更新 + 離線佇列 */
  send(roomId, body) {
    const clientMsgId = crypto.randomUUID();
    const payload = { type: 'message', client_msg_id: clientMsgId, room_id: roomId, body, sent_at: Date.now() };
    // 先回呼讓 UI 樂觀渲染(status=sending)
    this.onMessage?.({ kind: 'optimistic', msg: { ...payload, status: 'sending' } });

    if (this.ws?.readyState === WebSocket.OPEN) {
      this._send(payload);
    } else {
      this.outbox.push(payload);        // 斷線中:先存起來,重連後補送
    }
    return clientMsgId;
  }

  _send(obj) {
    try { this.ws.send(JSON.stringify(obj)); }
    catch { this.outbox.push(obj); }    // 送失敗也丟回佇列
  }

  _flushOutbox() {
    const pending = this.outbox;
    this.outbox = [];
    pending.forEach((p) => this._send(p));
  }

  /**
   * 指數退避重連:1s, 2s, 4s, 8s ... 上限 30s,並加入 jitter(隨機抖動)
   * 避免「驚群效應」—— 伺服器重啟時所有客戶端同一秒一起重連把它壓垮。
   */
  _scheduleReconnect() {
    if (this.retries >= this.maxRetries) { this.onStatus?.('failed'); return; }
    const base = Math.min(1000 * 2 ** this.retries, 30000);
    const jitter = Math.random() * 0.3 * base;   // ±30% 抖動
    const delay = base + jitter;
    this.retries += 1;
    this.onStatus?.(`reconnecting in ${Math.round(delay / 1000)}s`);
    setTimeout(() => this.connect(), delay);
  }

  /** 看門狗:一段時間沒收到任何訊息/心跳 → 視為連線已死,主動關閉觸發重連 */
  _armPongWatchdog() {
    clearTimeout(this.missedPongTimer);
    this.missedPongTimer = setTimeout(() => {
      if (this.ws?.readyState === WebSocket.OPEN) this.ws.close(); // → onclose → 重連
    }, 35000); // 須 > 伺服器 ping 間隔
  }

  close() { this.manualClose = true; this.ws?.close(); }
}

/** XSS 防護:渲染訊息一律跳脫,絕不用 innerHTML 直塞 body */
function escapeHtml(text) {
  const div = document.createElement('div');
  div.textContent = text ?? '';   // 瀏覽器自動跳脫 < > & " '
  return div.innerHTML;
}

/** 自動捲動:只有原本貼底時才捲到底,避免打斷正在翻歷史的使用者 */
function appendMessage(container, msg) {
  const nearBottom = container.scrollHeight - container.scrollTop - container.clientHeight < 80;
  const el = document.createElement('div');
  el.dataset.id = msg.server_id ?? msg.client_msg_id;
  el.innerHTML = `<span class="body">${escapeHtml(msg.body)}</span>`; // body 已跳脫
  container.appendChild(el);
  if (nearBottom) container.scrollTop = container.scrollHeight;
  else showNewMessagePill();      // 否則顯示「↓ 新訊息」提示
}

3-2. 後端伺服器端(Node.js + ws)

重點:交握時鑑權(verifyClient)、房間管理、伺服器層 ping/pong 清死連線、先持久化後廣播 + Redis 跨節點扇出、不信任客戶端身分。

const http = require('http');
const { WebSocketServer } = require('ws');
const jwt = require('jsonwebtoken');
const Redis = require('ioredis');

const JWT_SECRET = process.env.JWT_SECRET;
const ALLOWED_ORIGIN = process.env.ALLOWED_ORIGIN;

// 兩條 Redis 連線:一條 publish、一條 subscribe(同一條不能同時收發)
const pub = new Redis(process.env.REDIS_URL);
const sub = new Redis(process.env.REDIS_URL);

const server = http.createServer();
const wss = new WebSocketServer({
  server,
  // 交握階段鑑權:驗證失敗直接拒絕升級,連線根本不會建立
  verifyClient: (info, done) => {
    // 1. Origin 檢查,擋掉跨站的惡意 WS 連線(CSWSH)
    if (ALLOWED_ORIGIN && info.origin !== ALLOWED_ORIGIN) return done(false, 403, 'Forbidden origin');
    // 2. 驗 token
    try {
      const url = new URL(info.req.url, 'http://localhost');
      const token = url.searchParams.get('token');
      const payload = jwt.verify(token, JWT_SECRET);
      info.req.userId = payload.sub;   // 把可信的 userId 綁到 request,後面 socket 沿用
      return done(true);
    } catch {
      return done(false, 401, 'Unauthorized');
    }
  },
});

// ===== 房間管理 =====
// rooms: roomId -> Set<ws>(本節點上屬於該房間的連線)
const rooms = new Map();
function joinRoom(roomId, ws) {
  if (!rooms.has(roomId)) rooms.set(roomId, new Set());
  rooms.get(roomId).add(ws);
  ws.rooms.add(roomId);
}
function leaveAllRooms(ws) {
  for (const roomId of ws.rooms) rooms.get(roomId)?.delete(ws);
  ws.rooms.clear();
}
/** 把訊息推給「本節點」上該房間的所有連線(可排除送出者自己) */
function broadcastLocal(roomId, data, exceptUserId = null) {
  const set = rooms.get(roomId);
  if (!set) return;
  const raw = JSON.stringify(data);
  for (const client of set) {
    if (client.readyState === client.OPEN && client.userId !== exceptUserId) {
      client.send(raw);
    }
  }
}

// ===== 跨節點扇出:訂閱 Redis,收到別台 publish 的訊息就在本節點廣播 =====
sub.psubscribe('room:*');
sub.on('pmessage', (_pattern, channel, message) => {
  const roomId = channel.split(':')[1];
  broadcastLocal(roomId, JSON.parse(message));
});

// ===== 連線生命週期 =====
wss.on('connection', (ws, req) => {
  ws.userId = req.userId;     // 可信身分(來自交握鑑權,客戶端無法偽造)
  ws.rooms = new Set();
  ws.isAlive = true;
  ws.on('pong', () => { ws.isAlive = true; }); // 協定層 pong 回來 → 標記存活

  ws.on('message', async (raw) => {
    let data;
    try { data = JSON.parse(raw); } catch { return; }      // 壞封包丟棄

    // ---- 加入房間(需驗證該 user 確實是房間成員)----
    if (data.type === 'join') {
      if (await isMember(data.room_id, ws.userId)) joinRoom(data.room_id, ws);
      return;
    }

    // ---- 送訊息 ----
    if (data.type === 'message') {
      // 輸入驗證:長度上限、型別
      const body = typeof data.body === 'string' ? data.body.slice(0, 5000) : '';
      if (!body.trim()) return;
      // 權限:必須是該房間成員(不信任客戶端)
      if (!(await isMember(data.room_id, ws.userId))) return;

      // 1) 先持久化(以 client_msg_id 冪等),取得權威 server_id / seq
      const saved = await persistMessage({
        roomId: data.room_id,
        senderId: ws.userId,          // 用連線上的可信 userId,不用 data 裡的
        clientMsgId: data.client_msg_id,
        body,
      });

      const out = {
        type: 'message',
        server_id: saved.id,
        seq: saved.seq,
        room_id: data.room_id,
        sender_id: ws.userId,
        body,                         // 後端不需 HTML 跳脫,但前端渲染時必須跳脫
        created_at: saved.createdAt,
      };

      // 2) 對送出者回 ACK(讓其樂觀訊息轉為 sent)
      ws.send(JSON.stringify({ type: 'ack', client_msg_id: data.client_msg_id, server_id: saved.id, seq: saved.seq }));

      // 3) 跨節點扇出(本節點也會經 psubscribe 收到並廣播,故這裡只 publish)
      await pub.publish(`room:${data.room_id}`, JSON.stringify(out));
    }
  });

  ws.on('close', () => leaveAllRooms(ws));
  ws.on('error', () => ws.terminate());
});

// ===== 心跳:每 30 秒掃一次,清掉沒回 pong 的死連線 =====
const heartbeat = setInterval(() => {
  for (const ws of wss.clients) {
    if (ws.isAlive === false) { leaveAllRooms(ws); ws.terminate(); continue; } // 上輪沒回 pong → 死連線
    ws.isAlive = false;     // 預設死,等這輪 pong 回來才翻 true
    ws.ping();              // 送協定層 ping frame(0x9),客戶端會自動回 pong
  }
}, 30000);
wss.on('close', () => clearInterval(heartbeat));

server.listen(8080, () => console.log('WS server on :8080'));

四、安全與極端狀況檢查清單

安全

  • XSS:訊息一律 textContent / 跳脫渲染,絕不 innerHTML 直塞使用者輸入。
  • 身分不可偽造:sender_id 取自連線鑑權後綁定的 userId,忽略客戶端 frame 內的任何 id。
  • 交握即鑑權 + Origin 檢查:擋 Cross-Site WebSocket Hijacking;token 建議用短期票券或子協定,避免進 URL log。
  • 傳輸加密(WSS/TLS)、輸入長度上限、發訊頻率限制(rate limit)。

極端狀況

  • 斷線:指數退避 + jitter 重連、離線 outbox 補送、未 ACK 訊息標 failed 可重送。
  • 半開連線:雙向心跳(伺服器 ping/pong 清死連線 + 客戶端看門狗)。
  • 重複投遞:client_msg_id 冪等寫入 + 前端 server_id 去重。
  • 訊息亂序:伺服器單調 seq 排序、補洞;重連後以 last_seq 向 DB 補拉。
  • 驚群效應:重連退避加隨機抖動,避免伺服器重啟瞬間被同時重連壓垮。
  • 水平擴展:多 WS 節點 + Redis Pub/Sub 扇出,確保不同節點上的使用者互通。
