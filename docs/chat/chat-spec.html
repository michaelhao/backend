chat Specification

後台使用者之間一對一即時文字聊天的完整行為規格
威脅模型與限制：內部後台、非公網暴露；正式環境無對外網際網路連線 —— 即時推播採自架 Laravel Reverb(WebSocket),前端 pusher-js 連自家 server,不連外部雲端。
來源：docs/superpowers/plans/2026-06-15-backend-chat-system.md 實作：0e2f6e5 … 8d2ce56(feat/chat-system) 測試：tests/Feature/Chat/
本頁為供 PM / 前端討論的閱讀版;若與程式碼/測試不一致,以實際程式碼為準。每個 Scenario 右側標註對應的自動化測試(none 表示屬前端/即時行為,無直接後端測試)。

對話與存取

R1聊天頁存取與權限

GET /chats SHALL 渲染聊天頁(admin.chats.index),受 auth + permission middleware 保護,所需權限 Chat.index。所有後台角色皆可聊天:Chat.index 為 index 類權限,Admin(全權限)與 Viewer(各 index 權限)皆自動取得。未登入者 SHALL 被導向 /login。
Admin 可開聊天頁ChatConversationTest::test_admin_can_open_chat_index_view
GIVEN已登入的 Admin
WHENGET /chats
THEN系統回應 200
Viewer 也有聊天權限ChatConversationTest::test_viewer_can_access_chat_endpoint
GIVEN已登入的 Viewer
WHENGET /chats/unread-count(需 Chat.index)
THEN系統回應 200
訪客被導向登入ChatConversationTest::test_guest_is_redirected_to_login
WHEN訪客 GET /chats
THEN系統回應 302 導向 /login

R2開始 / 取得對話(canonical pair)

POST /chats/start 帶 target_user_id SHALL 取得或建立與該使用者的 1:1 對話並回傳 conversation_id。對話以 canonical pair 儲存(user_one_id < user_two_id),因此與順序無關、同一對組合永不重複建立,並 SHALL 建立剛好兩筆 participant。
建立對話含兩位參與者ChatConversationTest::test_start_creates_conversation_with_two_participants
WHENPOST /chats/start 帶另一使用者 id
THEN建立 1 筆 conversation
AND該 conversation 有 2 筆 participant
重複 / 反序回同一對話ChatConversationTest::test_start_is_idempotent_regardless_of_order
WHEN對同一對象連續 start 兩次
THEN兩次回傳相同 conversation_id
AND資料庫只有 1 筆 conversation
並發建立同一對話不重複ChatServiceTest::test_get_or_create_is_idempotent
GIVEN兩位使用者 A、B
WHEN以 (A,B) 與 (B,A) 各取得一次對話
THEN得到同一筆對話(unique index 兜底,撞鍵時取回既有)

R3對話對象限制

target_user_id SHALL 為 required|integer|exists:users,id,且 MUST NOT 等於自己。與自己建立對話或對象不存在 SHALL 回 422。
不可與自己對話ChatConversationTest::test_start_rejects_self
WHENPOST /chats/start 帶自己的 id
THEN系統回應 422
對象須存在ChatConversationTest::test_start_rejects_nonexistent_user
WHENPOST /chats/start 帶不存在的 user id
THEN系統回應 422
Service 層擋自我對話ChatServiceTest::test_get_or_create_rejects_self
WHENgetOrCreateConversation(uid, uid)
THEN拋出 ChatOperationException

R4對話列表

GET /chats/conversations SHALL 回傳目前使用者的對話清單,每筆含對方 {id,name}、最後訊息預覽、last_message_at 與未讀數,依 last_message_at 由新到舊排序。未讀數 SHALL 以單一查詢批次取得(避免 N+1)。
列表含對方與未讀數ChatServiceTest::test_list_conversations_includes_unread_count_and_other_user
GIVEN我與 B 的對話,B 送了 2 則
WHENlistConversations(我)
THEN該筆 other_user.id = B、unread_count = 2

訊息

R5送出訊息

參與者 POST /chats/{conversation}/messages SHALL 在單一交易內建立訊息並更新該對話的 last_message_id / last_message_at,然後 dispatch MessageSent,並回 201 帶該訊息。
參與者送訊息並廣播ChatMessageTest::test_participant_can_send_message_and_event_is_broadcast
GIVEN我與 B 的對話
WHENPOST 訊息 body="hi there"
THEN回 201、chat_messages 有該筆
ANDdispatch MessageSent,recipientId = B
持久化 + 更新 last_message + 發事件ChatServiceTest::test_send_message_persists_updates_last_message_and_dispatches_event
WHENsendMessage 送出一則
THENconversation 的 last_message_id 指向新訊息、last_message_at 非空
ANDMessageSent 已 dispatch

R6訊息驗證

body SHALL 為 required|string|max:5000。不合規 SHALL 回 422。
空白 body 被拒ChatMessageTest::test_body_is_required
WHENPOST 訊息 body=""
THEN系統回應 422

R7讀取與分頁

GET /chats/{conversation}/messages SHALL 回傳該對話訊息(依 id 由新到舊、單頁上限 30),並支援 before_id 游標往前載入更舊訊息。
以 before_id 取較舊訊息ChatMessageTest::test_messages_are_paginated_with_before_id
GIVEN對話內有 5 則訊息
WHENGET messages 帶 before_id=第3則
THEN回傳的訊息 id 皆 < 第3則

R8參與者授權(核心安全)

讀訊息 / 送訊息 / 標記已讀 SHALL 要求請求者為該對話參與者(canonical pair 之一);非參與者 MUST NOT 存取,回 403。對話不存在 SHALL 回 404(以 findOrFail 區分「找不到」與「沒權限」)。
非參與者不可送訊息ChatMessageTest::test_non_participant_cannot_send_message
GIVENowner 與 B 的對話
WHEN第三人 POST 訊息到該對話
THEN系統回應 403
非參與者不可讀訊息ChatMessageTest::test_non_participant_cannot_read_messages
WHEN第三人 GET 該對話 messages
THEN系統回應 403
對話不存在回 404ChatMessageTest::test_messages_on_missing_conversation_returns_404
WHENGET 不存在的 conversation messages
THEN系統回應 404
Service 對外人拋例外ChatServiceTest::test_assert_participant_throws_for_outsider
WHENassertParticipant 帶非參與者
THEN拋出 ChatOperationException(→ 403)

未讀

R9未讀計算

某對話對某使用者的未讀數 SHALL = 該對話中 sender_id != 自己 且(participant 的 last_read_at 為 null,或 created_at > last_read_at)的訊息數。自己送出的訊息不計入自己的未讀。
排除自己訊息、尊重 last_read_atChatRepositoryTest::test_unread_count_excludes_own_messages_and_respects_last_read
GIVEN對方送 2 則、我送 1 則
WHENlast_read_at 為 null 計算未讀
THEN未讀 = 2(我自己的不算)
ANDlast_read_at = 現在時未讀 = 0
跨對話加總ChatServiceTest::test_total_unread_counts_across_conversations
GIVEN兩個對話分別有未讀
WHENtotalUnread(我)
THEN回傳跨對話未讀總和

R10未讀總數 / 側欄 badge

GET /chats/unread-count SHALL 回傳跨所有對話的未讀總數,用於驅動側欄紅點 badge。前端在每個後台頁面載入時與收到新訊息時向此端點抓取權威數字(不靠本地累加,避免多分頁飄移)。
未讀總數端點ChatUnreadTest::test_unread_count_endpoint_returns_total
GIVEN對方送了 2 則
WHENGET /chats/unread-count
THENunread_count = 2

R11標記已讀

PATCH /chats/{conversation}/read SHALL 將該參與者的 last_read_at 設為 now() 並回傳更新後的未讀總數。非參與者 MUST NOT 標記,回 403。
標記已讀後未讀歸零ChatUnreadTest::test_mark_read_resets_unread
GIVEN對方送了 3 則
WHENPATCH /chats/{id}/read
THENunread_count = 0
非參與者不可標記ChatUnreadTest::test_non_participant_cannot_mark_read
WHEN第三人 PATCH 該對話 read
THEN系統回應 403

即時(自架 Reverb)

即時推播以自架 Laravel Reverb 提供;MessageSent 為 ShouldBroadcastNow,免額外 queue worker。

R12訊息廣播

MessageSent SHALL 廣播到接收者的 chat.user.{recipientId} 與送出者的 chat.user.{senderId}(讓送出者其他分頁同步),事件名 message.sent,payload 含 id, conversation_id, sender_id, sender_name, body, created_at。前端 SHALL 以訊息 id 去重,避免本地已顯示的自送訊息重複。
廣播頻道與 payloadChatMessageTest::test_participant_can_send_message_and_event_is_broadcast
WHEN送訊息給 B
THENbroadcastOn 第一個頻道為 private-chat.user.{B}
ANDbroadcastWith.conversation_id 正確

R13頻道授權

私有頻道 chat.user.{id} SHALL 僅授權本人;chat.conversation.{id} SHALL 僅授權該對話參與者;presence chat.online SHALL 對任何登入者授權(回 {id,name})。未登入者 MUST NOT 通過授權。
本人可訂自己的 user 頻道ChatChannelAuthTest::test_user_can_authorize_own_user_channel
WHEN授權 private-chat.user.{自己}
THEN通過(200)
不可訂他人 user 頻道ChatChannelAuthTest::test_user_cannot_authorize_another_user_channel
WHEN授權 private-chat.user.{他人}
THEN拒絕(403)
參與者可訂對話頻道 / 外人不可ChatChannelAuthTest::test_participant_can_authorize_conversation_channel · test_outsider_cannot_authorize_conversation_channel
WHEN授權 private-chat.conversation.{id}
THEN參與者通過、外人 403
登入者可加入 presence / 訪客不可ChatChannelAuthTest::test_authenticated_user_can_join_presence_channel · test_guest_cannot_authorize_channel
WHEN授權 presence-chat.online
THEN登入者通過、訪客 403

R14線上狀態

前端透過 presence 頻道 chat.online 維護線上使用者集合;對話對象在線時 SHALL 於對話標題列顯示綠點。頻道授權已由 R13 測試涵蓋;綠點本身為前端行為。
線上綠點(前端)無直接後端測試 — 雙帳號手動驗證
GIVEN對話雙方皆在線
WHEN開啟與對方的對話
THEN標題列顯示綠點;對方離線時消失

R15輸入中提示

於對話頻道 chat.conversation.{id} 以 Echo whisper('typing') 傳遞「對方輸入中」,MUST NOT 寫入資料庫(純 client 端 whisper,逾時自動消失)。
輸入中提示(前端 whisper)無直接後端測試 — 雙帳號手動驗證
WHEN對方在輸入框打字
THEN我看到「對方正在輸入…」,停止後約 2 秒消失

R16孤兒對話略過(韌性)

本專案 user 參照欄位無 DB 外鍵且刪除為實體刪除。若對話對象使用者已被刪除,對話列表 SHALL 略過該孤兒對話(對方為 null),MUST NOT 因存取 null 而錯誤。
對方被刪除時略過該對話ChatServiceTest::test_list_conversations_skips_conversation_whose_other_user_was_deleted
GIVEN我與 B 的對話,B 的帳號被刪除
WHENlistConversations(我)
THEN回傳不含該孤兒對話,且不拋錯
