admin-layout Specification

後台共用版型外殼、權限導向導覽、系統文件入口、頂部列登出、session 倒數計時器、無角色頁與訪客版型的完整行為規格
威脅模型：內部後台、非公網暴露（brute-force 不在 scope）；正式環境無對外網際網路連線（版型零外部資源依賴）。

本頁為人工同步的閱讀版；若與 spec.md 不一致，以 spec.md 為準。每個 Scenario 右側標註對應的自動化測試（版型多屬視圖／前端行為，部分無專屬測試）。

版型結構與導覽

R1後台版型外殼

所有後台頁面 SHALL 繼承 layouts/admin.blade.php，由其提供固定左側 sidebar（w-64）+ 頂部列 + 主內容區的三段式骨架。版型外殼 SHALL 提供：
  • @yield('content') 主內容插槽
  • @yield('page-title', 'Dashboard') 同時用於 <title> 與頂部列標題
  • @stack('scripts') 供子頁面注入頁面層級 JS
  • <head> 內 csrf-token、session-lifetime（值 = config('session.lifetime') * 60 秒）與 login-url（值 = route('login')）三個 meta
  • 透過 @vite 載入 app.css、app.js、layouts/admin.js
後台頁面套用版型外殼DashboardTest::test_admin_can_access_dashboard
GIVEN已登入且具 Dashboard.index 權限的使用者
WHENGET /
THEN系統回應 200 並渲染 admin.dashboard 視圖（繼承 layouts.admin）
AND回應含 sidebar、頂部列與主內容區
session-lifetime meta 以秒注入無直接測試 — 目視 admin.blade.php
GIVEN已登入使用者
WHEN開啟任一後台頁面
THEN<head> 含 <meta name="session-lifetime">，其值等於 config('session.lifetime') * 60

R2權限導向的側邊欄導覽

sidebar 每個 權限控管 選單連結 SHALL 以 <x-permission name="{Module}.index"> 元件包裹，僅在當前使用者持有該權限時渲染。Permission::shouldRender() SHALL 回傳 Auth::check() && hasPermissionTo($name)，權限來源為登入時載入的 session('auth.permissions')。active 標示 SHALL 以 request()->routeIs('{module}.*') 判斷。不進權限系統的連結（例如「系統文件」入口，見 R3）SHALL NOT 以 <x-permission> 包裹。
有權限者可見對應選單無直接測試 — 元件 shouldRender 邏輯
GIVEN持有 Shop.index 權限的使用者
WHEN開啟後台頁面
THENsidebar 顯示「商店管理」連結
無權限者不見對應選單無直接測試 — 元件 shouldRender 邏輯
GIVEN未持有 Shop.index 權限的使用者
WHEN開啟後台頁面
THENsidebar 不渲染「商店管理」連結
未登入時元件不渲染無直接測試 — 元件 shouldRender 邏輯
GIVEN未通過認證的請求情境
WHEN<x-permission> 嘗試渲染
THENshouldRender() 因 Auth::check() 為 false 而回傳 false，不渲染 slot

R3系統文件側邊欄入口

在 local 環境，sidebar 導覽列（<nav>）最上方（位於「儀表板」之前）SHALL 包含一個指向 route('docs.index') 的「系統文件」連結；此連結為開發人員導向，SHALL 以 Blade @env('local') 包裹，於 非 local 環境 SHALL NOT 渲染。因 /docs 路由置於 permission middleware 之外（登入即可瀏覽、不進權限系統），此連結 SHALL NOT 以 <x-permission> 包裹，且在 local 環境 SHALL 對所有已登入使用者顯示（含無任何管理權限者）。其 active 標示 SHALL 以 request()->routeIs('docs.*') 判斷，套用與其他導覽連結一致的 bg-blue-50 text-blue-600 樣式。
local 環境一般登入者可見系統文件入口DocsTest::test_docs_sidebar_link_visible_in_local
GIVENlocal 環境下已登入但未持有任何管理權限的使用者
WHENGET /docs
THENsidebar 顯示指向 route('docs.index') 的「系統文件」連結
非 local 環境不顯示系統文件入口DocsTest::test_docs_sidebar_link_hidden_outside_local
GIVEN非 local 環境（如 production、testing）的已登入使用者
WHENGET /docs
THENsidebar 不渲染「系統文件」連結
系統文件入口不受權限控管DocsTest::test_docs_sidebar_link_visible_in_local
WHEN於 local 環境渲染 sidebar
THEN「系統文件」連結未被 <x-permission> 包裹，對所有登入者一致顯示
進入文件頁時 active 樣式無直接測試 — 前端視覺
WHEN使用者於 local 環境 GET /docs
THENsidebar 中「系統文件」連結含 bg-blue-50 text-blue-600 樣式

R4頂部列使用者識別與登出

頂部列 SHALL 顯示當前頁面標題、Auth::user()->name、session 倒數計時器，以及一個 POST 至 route('logout') 的登出表單（含 @csrf）。
顯示登入者姓名無直接測試 — 目視 admin.blade.php
GIVEN名為「王小明」的已登入使用者
WHEN開啟後台頁面
THEN頂部列顯示「王小明」
登出表單以 POST 提交無直接測試 — 目視 admin.blade.php
WHEN渲染頂部列
THEN含 method="POST" 且 action 指向 route('logout') 的表單與 CSRF token

視覺與互動

R5Admin Sidebar 視覺主題

layouts/admin.blade.php 的 sidebar SHALL 採用淺色 + 藍品牌主題：
  • 容器：白底 + 右側細邊框（bg-white border-r border-slate-200）
  • Logo block：藍色品牌色站名（text-blue-600）；不留 border-b
  • active 樣式：藍色淺底（bg-blue-50）+ 藍色文字（text-blue-600），字重 font-medium
  • 非 active：text-slate-500 hover:bg-slate-100 hover:text-slate-700
  • 頂部列與 session 計時器（admin.js）灰階 token SHALL 統一 slate-*（不用 gray-*）
  • 8 個既有選單 SHALL 全部保留；早期「文章管理」（Post.index）佔位連結已移除（權限不存在故永不渲染）
進入儀表板時 active 樣式無直接測試 — 目視 admin.blade.php
WHEN使用者 GET /
THENsidebar 中「儀表板」連結含 text-blue-600 樣式
切到其他頁面時 sidebar 樣式仍為淺色無直接測試 — 目視 admin.blade.php
WHEN使用者 GET /users、/shops 等任一頁面
THENsidebar 維持白底淺色藍品牌
AND該頁面對應選單為 active 藍色樣式
8 個選單全保留無直接測試 — 目視 admin.blade.php
WHENadmin 角色使用者開啟 admin 頁面
THENsidebar 顯示全部 8 項既有選單（儀表板、使用者管理、角色管理、版本管理、商店管理、加購功能管理、帳務管理、說明會管理）
AND不再出現「文章管理」佔位連結

R6Session 倒數計時器

resources/js/layouts/admin.js SHALL 讀取 session-lifetime meta 作為起始秒數，於頂部列以 HH:MM:SS 每秒遞減顯示。剩餘 ≤ 300 秒時 SHALL 由 text-slate-400 切換為 text-red-500，> 300 秒時 SHALL 還原為 text-slate-400；歸零時 SHALL 導向 login-url meta（值 = route('login')，fallback /login）。顏色 class SHALL 與 markup 一致採 slate-*（修正先前 text-gray-400 的 no-op remove 死碼）。
此為純前端視覺提示，伺服器端 session 失效仍由 Laravel session middleware 權威處理。
倒數歸零導向登入頁無直接測試 — 前端行為
GIVEN後台頁面載入且計時器啟動
WHEN剩餘秒數遞減至 0
THEN瀏覽器導向 login-url meta 指定的位址（route('login')，fallback /login）
進入警示門檻變紅無直接測試 — 前端行為
GIVEN計時器運作中
WHEN剩餘秒數 ≤ 300
THEN計時文字移除 text-slate-400 並加上 text-red-500

輔助頁面

R7無角色 fallback 頁

GET /no-role（route name no-role）SHALL 渲染無角色提示頁，繼承 layouts.admin 並提供 POST 登出表單。此路由 SHALL 受 auth 保護但 不 進入 permission middleware 群組（避免無角色者被反覆導向）。當已登入使用者 role_id 為 null 時，permission middleware SHALL 將其導向此頁。
無角色使用者被導向 no-role 頁PermissionTest::test_user_without_role_is_redirected_to_no_role_page
GIVEN已登入但 role_id 為 null 的使用者
WHENGET /
THEN系統 302 導向 route('no-role')
no-role 頁提供登出無直接測試 — 目視 no-role.blade.php
WHEN渲染 /no-role
THEN頁面含 POST 至 route('logout') 的登出表單

R8訪客版型

登入、忘記密碼、重設密碼等 guest 頁面 SHALL 繼承 layouts/app.blade.php——置中、無 sidebar、僅載入 app.css 與 app.js 的精簡骨架，與後台 layouts.admin 分離。
登入頁使用訪客版型LoginTest::login_screen_can_be_rendered
WHEN訪客 GET /login
THEN頁面以 layouts.app 渲染（置中、無 sidebar）

刻意設計（不是缺漏）

以下為依威脅模型與簡化考量刻意排除的功能，避免後人誤判為待補項目。

R9刻意不做的範圍界線

基於內部後台、非公網暴露的威脅模型與簡化考量，本版型 SHALL 明確界定下列刻意不實作的範圍：
Session 活動式重置 / heartbeat計時器為單純倒數，MUST NOT 因使用者操作而重置（伺服器端到期仍由 Laravel session 處理）
RWD 行動 sidebar 收合sidebar 固定 w-64，MUST NOT 提供漢堡選單 / 收合控制；僅針對桌面內部後台
計時器不因操作重置無直接測試 — 前端行為
GIVEN後台頁面開啟且計時器運作中
WHEN使用者在頁面內持續操作（未換頁）
THEN計時器持續倒數，不重置回起始值
無行動裝置 sidebar 切換無直接測試 — 目視 admin.blade.php
WHEN檢視版型 markup
THEN不存在 sidebar 收合 / 漢堡選單的切換控制
