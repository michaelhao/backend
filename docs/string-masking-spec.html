string-masking Specification

App\Support\Mask 顯示遮蔽工具（字串奇數索引、email local part）的完整行為規格
威脅模型：內部後台、非公網暴露（brute-force 不在 scope）、能登入後台者即為受信任之內部人員。遮蔽定位為顯示層防肩窺、非機密控制；正式環境無對外連線，本功能無任何外部呼叫。

Mask::string() — 字串奇數索引遮蔽

Mask::string("12345678")
逐字元掃描以 mb_* 計數
多位元組安全
索引為奇數（1、3…）→ 換成 *
索引為偶數（0、2…）→ 保留原字元
"1*3*5*7*"

Mask::email() — 僅遮 local part

Mask::email("admin@test.com")
找 @ 位置
有 @：local 套 string()"admin" → "a*m*n"
接回 @test.com
"a*m*n@test.com"
無 @：整串套 string()退回遮蔽全部

遮蔽演算法

R1字串奇數索引遮蔽

App\Support\Mask::string(string $value): string SHALL 將輸入字串中索引為奇數（1、3、5…）的字元替換為 *，索引為偶數（0、2、4…）的字元保留原樣。計數 SHALL 以「字元」為單位（使用 mb_strlen / mb_substr），對多位元組字元安全。
例：12345678 → 1*3*5*7*　/　中文字 → 中*字
一般字串遮蔽奇數位MaskTest::test_string_masks_odd_index_characters
WHEN呼叫 Mask::string('12345678')
THEN回傳 1*3*5*7*
空字串原樣回傳MaskTest::test_string_returns_empty_for_empty_input
WHEN呼叫 Mask::string('')
THEN回傳 ''
單一字元不被遮蔽MaskTest::test_string_keeps_single_character_unmasked
GIVEN僅一個字元（索引 0 為偶數）
WHEN呼叫 Mask::string('a')
THEN回傳 a
多位元組字元以字元為單位遮蔽MaskTest::test_string_is_multibyte_safe
WHEN呼叫 Mask::string('中文字')
THEN回傳 中*字（不切斷 UTF-8 位元組）

R2email 局部遮蔽

App\Support\Mask::email(string $email): string SHALL 僅對 @ 之前的 local part 套用 Mask::string()，@ 與其後網域部分 SHALL 原樣保留。輸入不含 @ 時 SHALL 退回對整串套用 Mask::string()。
例：admin@test.com → a*m*n@test.com　/　abc@gmail.com → a*c@gmail.com
遮蔽 local part 並保留網域MaskTest::test_email_masks_local_part_only
WHEN呼叫 Mask::email('admin@test.com')
THEN回傳 a*m*n@test.com
短 local partMaskTest::test_email_masks_short_local_part
WHEN呼叫 Mask::email('abc@gmail.com')
THEN回傳 a*c@gmail.com
無 @ 退回整串遮蔽MaskTest::test_email_without_at_masks_whole_string
WHEN呼叫 Mask::email('no-at-sign')
THEN回傳 n*-*t*s*g*（等同對整串套用 Mask::string）
單字元 local part 不被遮蔽MaskTest::test_email_with_single_char_local_part_is_not_masked
GIVENlocal part 僅一字元（索引 0 為偶數）
WHEN呼叫 Mask::email('a@b.com')
THEN回傳 a@b.com
空 local partMaskTest::test_email_with_empty_local_part
WHEN呼叫 Mask::email('@test.com')
THEN回傳 @test.com

整合約束

前後端為同演算法的雙端實作，須一併維護。

R4前後端遮蔽演算法一致（設計約束）

前端 resources/js/shops/edit.js 的 maskString() 與 App\Support\Mask::string() SHALL 維持相同演算法（奇數索引換 *）。任一端調整遮蔽規則時 MUST 同步另一端，以免認證當下前端即時顯示與重新載入後伺服端渲染不一致。此跨語言一致性無自動化測試守護，改以 edit.js 註解指回 App\Support\Mask 與本約束守護。
認證後前端遮蔽與重載後伺服端遮蔽一致無自動化測試（跨語言）— edit.js 註解守護
GIVEN統一編號 12345678
WHEN前端認證成功即時呼叫 maskString('12345678')，其後重新載入頁面由 Mask::string('12345678') 渲染同一欄位
THEN兩者皆顯示 1*3*5*7*

刻意設計（不是缺漏）

以下為依架構與威脅模型刻意如此的設計，避免後人誤判為待補項目。

R3不以全域函式提供遮蔽（刻意設計）

遮蔽邏輯 MUST NOT 以全域函式（maskString()、maskEmail()）提供。原 app/Helpers/MaskHelpers.php 全域函式已由 commit 186da22 整檔移除（前置重構 816ad29 先將邏輯遷入 App\Support\Mask）。PHP 端 SHALL 一律透過 App\Support\Mask 靜態類別呼叫，以利 PSR-4 autoload、IDE go-to-definition 與靜態分析建立呼叫圖。Mask::email() 內部 SHALL 呼叫 Mask::string()，使依賴關係明確可見。
程式庫不存在全域遮蔽函式無直接測試 — grep / code review 守護（佐證 186da22）
WHEN檢視程式庫
THEN不存在 app/Helpers/MaskHelpers.php
AND不存在全域 maskString() / maskEmail() 函式定義
AND所有 PHP 遮蔽呼叫皆為 App\Support\Mask::string() / ::email()

R5遮蔽僅為顯示層、非機密控制（刻意設計）

App\Support\Mask SHALL 僅用於 UI 顯示遮蔽。系統 MUST NOT 將遮蔽視為機密邊界或存取控制：被遮蔽欄位的真值仍會隨頁面送至前端（如商店編輯頁的可編輯 input 與 hidden input）。依威脅模型（內部後台、非公網暴露、能登入後台者即為受信任之內部人員），此為可接受的刻意設計。
商店編輯頁同時含遮蔽顯示值與真值ShopRuTest::test_admin_can_access_shop_edit（遮蔽顯示）
GIVEN持 Shop.update 權限者開啟商店編輯頁，管理員 email 與統一編號已遮蔽顯示
WHEN檢視頁面 DOM
THEN遮蔽顯示值存在於唯讀欄位
AND對應真值仍存在於可編輯 / hidden 欄位（遮蔽不阻止有權限者取得真值）

—刻意不做的事（彙整）

全域 helper 函式不提供 maskString() / maskEmail() 全域函式；MaskHelpers.php 已移除（R3）
把遮蔽當機密控制真值仍隨頁面送至前端，遮蔽僅降低肩窺風險，非存取控制（R5）
可設定遮蔽策略不提供自訂遮蔽字元 / 固定長度遮蔽；非現狀需求，不臆測擴充
